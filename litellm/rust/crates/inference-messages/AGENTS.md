- Shared base and layering rules: [`../inference/AGENTS.md`](../inference/AGENTS.md)
- This crate owns provider-independent Messages call orchestration: the entrypoint, call envelopes, provider selection, credential resolution, transport coordination, hooks, and stream lifecycle
  - shared API data contracts belong in `litellm-llms-types::formats::messages`
  - adapter contracts and execution inputs in `llms/src/base_llm/messages`
  - provider implementations in `llms/src/<provider>/messages`
- Select concrete provider adapters and invoke their contracts
  - delegate authentication policy, beta selection, payload rewriting, and response interpretation to those adapters
  - keep provider policy out of request preparation and transport handlers
  - calling a concrete provider helper for every provider is still a policy dependency
- Route types such as `MessagesCall`, provider calls, and response wrappers containing live streams describe execution. Reuse the shared Messages payload types inside them instead of defining another request or response schema here
- The route returns `litellm_host::call::CallOutput`: a completed response, or a stream head and chunks
- Per-call dependencies are grouped in `litellm_inference::context::CallContext`. `handler::execute` explicitly sequences the provider call build in Python's handler order, cache lookup, provider execution, result acceptance (`CallContext::result_ready`), and cache storage
- Preserve the order of validation, normalization, caller-requested parameter removal, and provider transformation when that order affects observable behavior
- Test provider dispatch, auth precedence, header handling, transformations, and responses through behavior, not source structure
- `tests/messages/conformance.rs` runs every native provider through the same cases against goldens recorded from main. Never hand-edit a golden. Rerun with `LITELLM_UPDATE_GOLDENS=1` only for an intended wire change, and review the diff
- Pricing: `usage.rs` reads Anthropic wire usage into the pricing core's `TokenUsage` (main's `calculate_usage` then `billed_usage`), and `pricing.rs` prices a finished call through the host's `Pricing` when the call carries a `PricingIdentity`. `price_call` is the generic `Pricing` body any host can use: it reads a `PricedCall` into litellm-cost's `TokenCall` and prices it over the host's `PricingTable` (a `CostLookup` over `Catalog` or the Python bridge's live view). `Pricing` itself stays a host trait, because only the host knows how to take one consistent view of its table per call
  - a message body is priced at `result_ready`. A stream gets a `StreamMeter` there and is priced at its `message_stop` (or its end) from `message_start` merged with the final `message_delta`, the way Python's `_handle_usage` merges them
  - anything main prices outside the token path stays `Deferred`: a missing identity, thinking text without reported counts, server web searches, a stream that ended before its terminal `message_delta`, a host-answered call
  - with stream cost injection on, the route writes `usage.cost` only into a usage event it prices and passes any other one through untouched, so the proxy's Python injector prices it as main did (`process_chunk_with_cost_injection` skips only events that already carry `cost`)
  - `fixtures/usage_parity.json` was captured once from main's Python (`calculate_usage`, the stream assembly, `priced_usage`) for every P1 provider's body and stream. Recapture it from main when a case must change
