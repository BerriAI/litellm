The price vocabulary (meter, band, channel, `When`, `Billing`) is explained in [../model-catalog/AGENTS.md](../model-catalog/AGENTS.md#concepts), the only crate that maps it to JSON keys

`candidates/` is completion_cost's candidate walk for the `/v1/messages` Claude providers (`CostProvider`): which names to try in which order, deployment rows by id, which provider to bill as, and when main would price another way (`AfterRows::Deferred` with its `Deferral`, so Python keeps pricing it). Rows before a deferral are still tried first, because main tries them first. It reads a catalog only through `CandidateTable`, which model-catalog implements, so this crate never depends on model-catalog. Its parity tests run in model-catalog (`resolve/candidate_walk.rs`), the only place both are visible
