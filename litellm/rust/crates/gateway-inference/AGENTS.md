- Expose a mountable Axum router. Listener binding, server lifecycle, and shared inbound middleware belong to `gateway`
- Own endpoint paths, request parsing, model alias resolution, and API-specific response and SSE error formats. Delegate hosted call execution and HTTP body delivery to host-http
- Delegate inference execution to the `inference-<fmt>` crates and provider transformations and authentication to `llms` and the auth crates. Do not duplicate them in handlers
- Let the `inference-<fmt>` crates validate inference fields and supported features, then map their errors to HTTP responses. Do not add gateway checks for temporary inference limitations
- `JsonObject` takes a body already parsed from the request's extensions and still reads the body, so the body limit holds. Whoever reads the body before the route puts it there, as the gateway's `admit` does, so a request is parsed once
- Use injected deployments, HTTP pools, settings, and secret sources. Do not load process configuration or construct independent clients in handlers
- Test HTTP contracts here, including status codes, forwarded headers, error envelopes, and streaming behavior. Keep inference and provider tests in their owning crates
- Routes go through router-core in `routing.rs`: `call` answers a name the router does not know as unknown and hands the core a `RouteAttempt` per route. The caller is the `Authenticated<H::Rows>` the mounting server's layer put on the request, which is `gateway-auth-core`'s `Caller`. The router's `proxy_admin` is `Caller::role`, never the kind of credential, and the cache scope names a key by `Caller::hash`. Whether a caller may be served a model is `gateway-auth-core`'s `authz::authorize`: `Host::layers` yields the model lists the host read for the caller, the route adds what the router resolves the name to (its group and access groups), and the core decides, before the call and for each fallback target (`routing::allows`). A route never names a row type and never compares a list, and `RouterRequest::allowed_models` is filled from the same layers. Every other hostcall is answered by the `Host` the `Gateway<H>` was built with. This crate implements no router-core host trait, so the routes never learn which host serves them
- A streamed attempt is served deferred, so the core only counted its request. `stream_outcome.rs` watches the stream's events as they pass and tells the core how it went: a success with the tokens the stream counted once it ends, or a failure when it breaks or carries the provider's error event. A Messages error event is the failure the same error is before a stream opens, with the status of `MessagesErrorType::status`, so a 400-type event cools nothing down and an overloaded one does. This differs from the Python proxy on purpose, which records a stream that goes out with an error event as served. A new streaming route wraps its chunks with `reporting_outcome`
- `stream_event.rs` holds the words the shared stream code asks an event in: whether content began, what it counts and whether it is the provider's error with the answer that error gets before a stream. Each streaming route keeps the one reader of its own format next to the route, as `messages::read_event`, matching on the format's event type in `llms-types` instead of reading raw JSON. `stream_outcome.rs` and `stream_hold.rs` ask that reader and never read a format themselves
- A served stream is held in `routing::call` while it has sent no content and the core's `may_take_over` says a retry or a fallback could still answer (`stream_hold.rs`). The hold knows streams only: it hands back either the committed stream or a `Failed` with what the stream sent, how it failed and what is left of it, and `routing.rs` turns that cause into the failure the core reads and the error a call ends on. When the provider fails a held stream, by an error event or a break, the core's `take_over_stream` decides whether an attempt may answer in its place and runs the retry in its group and then the fallbacks. `routing.rs` orders none of that itself and starts from the `origin` on the response it was handed. The failed stream is closed before the take-over runs, and a take-over that serves nothing ends the call on the provider's error as an HTTP answer, with the routing headers of the stream that failed. With no attempt to answer, an error event goes out as the provider sent it, and a stream that broke ends the call on that failure, since nothing reached the client yet. The stream that answers is held the same way. A route opts in by answering `RouteAttempt::held` with its stream and the reader of its format. Keepalives are held with the rest, since the response head is only written once the stream settles
- The hold keeps at most `stream_hold::HELD` of a stream, in blocks and in bytes, and commits a stream that sends more. It sets no timeout of its own: the attempt's timeout bounds the whole upstream response, so it is what ends a held stream that sends nothing
- An error the core makes itself is answered in Python's status and words. `routing::call` turns the core's no-deployments refusal into `NoDeployments`, which reads as `RouterRateLimitError` does. Add a variant the same way before a new core refusal can reach a client, never the core's own `Display` text
- Every route tells the host's callback hooks what happens to its call through `CallHooks` (`hooks.rs`), which `Host::hooks` hands it for each request: `pre_call` before the call is routed, `post_call_success` on a complete answer only, `response_headers` on every served answer, then `succeeded` or `failed`. `hooks.rs` owns that order and `serve::run` is its one caller, so a route never calls a hook itself: `hooks::around` wraps the call with `pre_call`, the success log of a complete answer and `failed`, and `hooks::answered` tells the outcome that served it, a stream through the same `stream_outcome::watched` the router hears it from. The route never learns which callbacks hear it, and renders a refusal as any other error in its own envelope. A new route names its `CallType` on its `Endpoint`, as Python's `call_type` for it
- A route tells what its call used as Python's litellm `Usage`, the shape Python's success log hands every callback: `/v1/messages` builds it with `usage_from_parts` (cache tokens folded into the prompt), from a complete answer or from the stream's events. A route names its conversion as `Endpoint::usage`, next to the reader its `RouteAttempt::held` names, so one format's counts are never converted as another's. OCR counts no tokens
- `routing::timeout` is the one place an attempt's timeout is decided, in the order of Python's `resolve_llm_passthrough_timeout`. The request's own `timeout` and the service-tier timeouts are not read yet. `litellm_settings.request_timeout`, the last one Python reads, is the messages shaping's `request_timeout`, which `inference-messages` falls back to when the attempt has no timeout
- `RateLimited` is the proxy's `ProxyRateLimitError`. `RateLimited::response` is the answer Python's authentication gives before any handler, in each route's envelope with the limit's headers, which the gateway's limit check before the body answers with. Turned into a `Refusal`, it is what a route's handler answers: the OpenAI routes the same body and headers, and `/v1/messages` its plain error without the limit's headers or the error type the proxy adds
- `asked::call_type` names the proxy's `CallType` for a matched path, for the gateway's `admit`, which has to know before the route runs which bodies only Python estimates
- Each request on the inference routes has one `CallRecord` (`record.rs`), what the route, the callbacks and every later reader know of the call. `record::scoped`, the outermost layer of `router`, makes it and runs the handler, every layer inside and the response body with it in a task-local, so code reaches it through `record::read`, `record::write` and `record::add_header` and never takes it as a parameter. A read or write with no record in scope is a bug: debug builds panic and release builds log it. A task spawned for a call goes through `record::spawn_in_call`, so it keeps the record
