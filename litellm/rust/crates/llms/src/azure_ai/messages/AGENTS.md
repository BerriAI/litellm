# rules

- Claude on Azure AI Foundry: reuses `anthropic/messages` shaping with the Azure `/anthropic` path
- Auth follows Python's `BaseAzureLLM._base_validate_azure_environment` order: the call's key, `litellm.api_key`, `litellm.azure_key`, `AZURE_OPENAI_API_KEY`, `AZURE_API_KEY`, each skipped only when empty, sent as `x-api-key`
- Without a key, and only when a Python host is wired in (`AzureAdTokenHosts::host`), the config walks Python's `get_azure_ad_token` order, reading every setting from the call and then where Python reads it: `AZURE_AD_TOKEN` through the secret lookup (`get_secret_str`, deferred through `deferred_secret_names`), the other Entra variables from the process environment (`os.getenv`), all only when there is no key and no caller `api-key` spelled exactly so. A static token, the caller's provider and client secret run natively (`litellm-auth-azure`). Username and password, OIDC references, `os.environ/` references, an uncallable provider and token refresh go to the host's `get_azure_ad_token`, so Python orders and mints those. No token sends the call unauthenticated. Without a Python host, as in the Rust gateway, a missing key is the `MissingApiKey` error main raised, whatever Entra ID settings the deployment holds
- The native client secret flow fetches its token as azure-identity does over `requests` (`TokenTransport::PythonRequests`): the proxy is urllib's `https_proxy` or `all_proxy` unless `requests`' `no_proxy` matching skips the host, the CA is `REQUESTS_CA_BUNDLE` or `CURL_CA_BUNDLE`, else Mozilla's roots, `SSL_CERT_FILE` is never read, and connect and read time out after azure-core's 300 seconds. Other `litellm-auth-azure` consumers keep azure_core's own transport
- The base is Python's `api_base or get_secret_str("AZURE_API_BASE")`: `AZURE_API_BASE` is a deferred secret read only when the call's base is empty, and the URL is cut at `/anthropic` in the path only, untrimmed, as `azure_anthropic_messages_url` does
- Caller credentials go out exactly as Python's dict and client send them (owner ruling, 2026-11-13). A caller `api-key` spelled exactly so replaces the deployment key and the Entra ID path. Otherwise the deployment key is added as `api-key`, or the Entra ID token as `Authorization` (replacing only that exact key), beside the caller's headers. `api-key` is renamed to `x-api-key` unless `x-api-key` is spelled exactly so, and names that differ only in case are joined into one header with `, `
- `anthropic-beta` goes through the `azure_ai` row of `anthropic_beta_headers_config.json` as Python's handler filters it: unknown and unsupported betas are dropped, the caller's and the ones the request needs alike
- The beta-gated system field strip, system-role normalization and the `cache_control.scope` strip run in `finalize_request`, after the betas are picked from the request as sent, in the order Python's transform runs them
- This config alone reads messages and system prompts Rust could not type as Python does (`UnparsedMessages::Read`): the sanitizer, advisor and encrypted-reasoning strips rewrite them and their beta triggers count. Every other provider, `anthropic` included by the owner's ruling, keeps main's behaviour: such messages go as sent, and a system prompt that does not parse is main's request error (`messages_body`)
