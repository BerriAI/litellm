Under load, 5 requests a second

Open-loop arrivals, 60 s warmup then 240 s measured per run. Requests use a 45k to 55k token input with tools and stream 1k to 4k output tokens from a mock that paces tokens at 12.5 ms. Each value is the median over the night's runs. The change column is the median of the per-round differences, with a bootstrap 95% interval, since both builds ran back to back in every round.

One request at a time

One user and an instant mock, 300 warmup then 1,500 measured requests per run. This isolates CPU per request. The next request starts the moment the previous stream ends, so work a build does after the stream closes lands on the next request's pre-upstream time and time to first token.

Run by run

Each dot is one run, in the order they ran overnight. Both builds ran in every round, so a gap that holds across rounds is the build, and shared ups and downs are the machine.

Where the CPU goes

Merged py-spy profiles at 5 req/s and 50 Hz, scaled to each build's measured CPU per request under load. The table compares subsystems, the flame graph shows one build at a time. Click a frame to zoom into it, click the top bar or Reset to zoom out.

Spread is the standard deviation across the profiled runs of that build. Subsystems are assigned from the innermost frame that matches, the same rules as flame.py.
